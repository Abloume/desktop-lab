# 学习路线：桌面端应用体系化重建（自查向）

定位：**已有 Electron 实战经验，但知识不成体系、表达不稳定**。缺的不是「会写」，而是成体系的知识框架、能讲清楚的自查表述，以及对周边知识（Tauri 对比、打包、安全）的覆盖。

方法：每个主题 = 一个最小可运行 demo + 一段「自查表述」，最后用模拟问答验收。

## 阶段 0：能力盘点（第 1 周）

目标：先知道自己哪里薄弱，再决定学什么。

对着下面的自测清单逐项打分（能讲清楚 = 3 分，知道大概 = 2 分，只会用 = 1 分，没概念 = 0 分），低于 2 分的项就是重点：

| 主题 | 自测分 | 自查追问 |
| --- | --- | --- |
| 进程模型 | | 主进程/渲染进程怎么分工？为什么要多进程？ |
| IPC 与安全 | | contextIsolation 是什么？为什么不能开 nodeIntegration？remote 模块为什么被移除？ |
| preload 与 contextBridge | | preload 存在的意义？暴露 API 的正确姿势？ |
| 生命周期 | | ready / window-all-closed / activate / will-quit 各在什么时机触发？ |
| 窗口管理 | | 无边框窗口怎么做拖拽？多窗口怎么通信？ |
| 打包分发 | | asar 是什么？签名/公证流程？自动更新怎么做？ |
| 性能优化 | | 为什么 Electron 内存高？启动怎么优化？ |
| 与 Web 开发的区别 | | 渲染进程为什么没有跨域问题？file:// 下有什么限制？ |
| Tauri 对比 | | Tauri 和 Electron 的架构差异？体积/性能/安全怎么对比？ |

产出：一张自测表提交进仓库（docs/skill-check.md 或直接改本文件）。

## 阶段 1：主题式重建（第 2–5 周）

目标：每个薄弱主题建一个小 demo，并写一段能「讲 1 分钟」的自查表述。

统一套路：
1. 写最小 demo（放 electron-lab/lessons/<主题>/）
2. 写一页笔记：一句话结论 → 展开要点 → 常见追问 → 我的表述
3. 表述按「结论先行 + 为什么 + 怎么做 + 坑在哪」组织

主题顺序（按依赖关系）：
1. **进程模型与生命周期**：从整体架构讲起，80% 的知识主线从这里切入
2. **IPC + 安全模型**：最容易被追问的深水区，必须能讲透 contextIsolation / sandbox / CSP
3. **窗口与界面**：无边框、多窗口、菜单/托盘/通知
4. **Node 能力与系统集成**：文件、剪贴板、快捷键、单实例锁
5. **打包分发**：asar、electron-builder、签名、自动更新
6. **性能与常见坑**：启动优化、内存、GPU 崩溃、远程内容风险

产出：每个主题一个提交（demo + 笔记），本阶段结束能脱离教程复述全部主题。

## 阶段 2：Tauri 对比学习（第 6–8 周）

目标：把「会写」升级成「能对比、能选型」，这是加分区和知识体系的收口。

- 先跑通 tauri-lab（补 Rust 基础：所有权/借用、Result、trait）
- 同一功能在 Tauri 里再实现一遍（文件读写、系统通知、托盘）
- 完成 docs/electron-vs-tauri.md 里的对比实验（体积/内存实测），把经验值换成自己的实测数据

产出：Tauri 侧每个功能一个提交 + 实测对比表更新。

## 阶段 3：自查演练（第 9–10 周）

目标：把笔记变成「说得出的话」。

- 每个主题 2–3 个高频问题，自己先答，再对照笔记补漏
- 手写题演练：主进程 → 渲染进程的完整安全链路、无边框窗口拖拽、IPC 批量传输优化
- 模拟「项目深挖」：把实战项目中做过的 Electron 点整理成 STAR 表述（做什么/为什么/难点/结果）

产出：docs/self-check-qa.md（问题 + 参考表述），本阶段结束能用 10 分钟讲完整个知识体系。

## 验收标准

- [ ] 自测表上每个 < 2 分的主题都补成了 3 分
- [ ] 每个主题能先讲结论、再讲原理、最后讲坑
- [ ] 能现场对比 Electron / Tauri 并给出选型判断
